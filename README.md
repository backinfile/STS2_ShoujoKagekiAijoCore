# ShoujoKagekiAijoCore 使用说明

本文面向使用 Core 的玩家和 Mod 作者，说明 Core 1.5.0 的能力、配置与 API V1 接入方式。SDK 随完整 Core 构建产物提供。

引导、服务端、存档与发布方面的实现约定见 [Core 实现文档](docs/IMPLEMENTATION.md)。[GitHub 仓库](https://github.com/backinfile/STS2_ShoujoKagekiAijoCore)

## 1. Core 提供的能力

Core 是少女歌剧系列 Mod 共用的基础 Mod，作为独立创意工坊 Mod 发布。Karen 的工坊包内嵌 Core；Junna 及其他依赖 Core 的 Mod 通过创意工坊依赖取得 Core。

| 能力 | 默认行为 |
| --- | --- |
| 公共配置 | 提供显示、音乐、遗物策略与上传设置 |
| 长颈鹿启动画面 | 游戏启动时统一播放一次 |
| 对局数据收集 | 自动读取原生对局记录、角色和 Mod 来源并上传 |
| 报错收集 | 自动收集标准错误、引擎错误和托管异常并上传 |
| 对局与报错 Web 页面 | 使用统一数据提供对局、统计和调用栈查询 |
| 闪耀相关能力 | 自动处理闪耀规则与配套表现 |
| 衍生牌标记 | 为战斗中生成且没有永久牌组来源的牌显示“衍生牌” |
| 音乐播放器 | 统一播放器、内置曲库、本地目录、播放控制和设置 |
| patches | 按配置启用公共兼容补丁 |
| 存档与历史 | 自动保存共享状态、规则版本和耗尽档案 |
| 作者工具 | 按发行能力提供卡牌导出、重放、移牌与音频辅助 |

Core 支持《杀戮尖塔 2》正式版与测试版。首版适配参考正式版 0.107.1、测试版 0.111.0 和 BaseLib 3.4.7，实际支持范围以对应发行说明为准。

## 2. 安装、加载顺序与更新

使用 Karen 时，更新 Karen 订阅即可取得内嵌 Core。使用 Junna 或其他依赖 Core 的 Mod 时，订阅该条目列出的 Core 和 BaseLib 必需物品。手动安装时，将完整 `ShoujoKagekiAijoCore` 目录与角色目录放入游戏 mods 目录，并安装该发行版要求的 BaseLib。

### 2.1 加载顺序

**BaseLib → ShoujoKagekiAijoCore → 角色 Mod。**

| 先后 | Mod |
| --- | --- |
| 1 | BaseLib |
| 2 | ShoujoKagekiAijoCore |
| 3 | ShoujoKagekiAijoKaren、ShoujoKagekiJunna 或其他依赖 Core 的角色 |

依赖 Core 的角色在清单中声明 Core 依赖，Core 在自己的清单中声明 BaseLib 依赖。本体按清单关系排列加载顺序，手动调整列表时也遵循上表。角色额外依赖其他库时，将这些库放在该角色之前。

启动提示会指出依赖问题及处理方式。例如“缺少 BaseLib，请安装 3.4.7 或更新的兼容版本”“Core 版本过低，该角色要求 1.2.0”或“加载顺序需要调整，请按 BaseLib → Core → 角色 Mod 排列”。

### 2.2 多角色与更新

独立 Core 与 Karen 内嵌 Core 同时安装时，引导器选择满足已启用角色要求的共同兼容版本。Core 的逻辑 Mod ID 固定为 `ShoujoKagekiAijoCore`，公共配置和共享状态按这个身份管理。

独立 Core 随其工坊订阅更新，Karen 内嵌 Core 随 Karen 订阅更新。游戏启动后，本次进程使用选定的 Core 业务版本，更新在下次启动时采用。角色与 Core 的接口要求在启动阶段检查，版本信息和具体缺失能力通过诊断状态提供。

## 3. 公共配置

Core 首次运行创建自己的默认配置，后续读取并升级 Core 自身配置。“一键解锁全部”按钮可解锁当前档案的角色、卡牌、遗物、药水、时间线与进阶等级，操作前备份原进度。请在主菜单使用。

| 常用配置 | 默认值 |
| --- | --- |
| 闪耀牌堆按钮 | 仅少歌角色显示 |
| 衍生牌标记 | 仅少歌角色显示 |

两个显示选项均提供“显示／仅少歌角色显示／关闭”。衍生牌标记按卡牌拥有者的角色判断，修改后即时刷新已有卡面。

长颈鹿启动画面位于配置页最顶部，默认开启。“特效”分组提供特效等级（完整／低／关闭）与闪耀相关特效，默认完整、开启。Karen 的专属特效使用 Core 的特效等级。分组顺序为“特效／音乐播放器／Patches／信息采集”，全部默认折叠。

“Patches”分组分别列出五轮书和招财异鱼，每件遗物独立选择战斗限制：

| 选项 | 生效方式 |
| --- | --- |
| 启用 | 所有角色持有时，这两件遗物仅在战斗外触发 |
| 仅对少歌角色启用 | 少歌角色持有时仅在战斗外触发，其余角色使用本体行为。默认选项 |
| 关闭 | 两件遗物使用本体触发规则 |

作用范围按遗物拥有者的角色判断。设置在新局建立时保存到对局，读档沿用该局设置，配置修改用于下次新局。

音乐设置集中在默认折叠的“音乐播放器”分组。

| 音乐配置 | 默认值 |
| --- | --- |
| 音乐播放器 | 开启 |
| 音乐目录 | 内置曲库，支持选择本地目录 |
| 播放模式 | 列表播放，可切换随机播放和单曲循环 |
| 播放／暂停快捷键 | F8 |
| 下一首快捷键 | F9 |
| 上一首快捷键 | F7 |

Core 在每个本地对局提供一个播放器，适用于当前本地角色。播放器提供音量、静音和展开／收起操作，初始音量为 70%，每局初始收起。进入对局后由玩家开始播放。播放器音量跟随游戏音乐音量共同生效。本地目录读取 MP3、OGG、WAV 文件。

“信息采集”分组包含总开关、上传对局数据、上传报错，默认均开启。关闭总开关时暂停两个上传通道并停止报错采集，保留子开关选择。对局上传和报错上传分别控制。关闭上传后暂停对应的新请求，已经发出的请求按原请求结束。对局队列保留待处理记录，重新开启后恢复。关闭报错上传同时停止新错误采集并清空内存聚合，已落盘的报错队列暂停，重新开启后恢复。

Core 使用 Karen 现行发行配置中的接收地址，Web 页面入口由对应部署提供。

## 4. Mod 作者使用方式

以下接口使用 ShoujoKagekiAijoCore.Api.V1。可编译示例与打包工具见 sdk/。

### 4.1 引用与工坊依赖

1. 从 Core GitHub 发行版取得 SDK 和完整 Core 分发目录。
2. 编译引用所需公开接口程序集。
3. 在角色清单声明 BaseLib、Core 依赖。
4. 使用 `sdk/pack-character.ps1` 生成角色的需求声明和构建锁文件。
5. 除 Karen 外，在角色工坊配置的 `dependencies` 中声明独立 Core 条目和 BaseLib 的工坊 ID。Karen 的上传目录内嵌完整 Core，工坊依赖为 BaseLib。

```xml
<Reference Include="ShoujoKagekiAijoCore.Api.V1">
  <HintPath>vendor/core-sdk/api/ShoujoKagekiAijoCore.Api.V1.dll</HintPath>
  <Private>false</Private>
</Reference>
```

角色清单示例。

```json
{
  "id": "ExampleCharacterMod",
  "version": "1.0.0",
  "has_dll": true,
  "has_pck": true,
  "affects_gameplay": true,
  "dependencies": [
    { "id": "BaseLib", "min_version": "3.4.7" },
    { "id": "ShoujoKagekiAijoCore", "min_version": "1.0.0" }
  ]
}
```

Core 自动读取本体已经发现的 Mod、角色、模型与牌池。接口版本和功能需求元数据由 SDK 打包工具生成。

游戏清单中的 `dependencies` 使用 Mod ID，工坊配置中的 `dependencies` 使用工坊条目的数字 ID。打包命令和两种分发方式见 [SDK 说明](sdk/README.md)，Core 自身发布流程见 [发布说明](docs/RELEASING.md)。

### 4.2 声明闪耀次数

在卡牌类上声明初始闪耀次数，Core 自动完成发现、状态初始化、关键字显示、计次、耗尽、存档与历史记录。

```csharp
using ShoujoKageki.Core.V1;

[ShineCard(6)]
public sealed class MyShineCard : MyCharacterCard
{
    // 费用、类型和具体牌效沿用角色自己的实现。
}
```

`ShineCard(6)` 表示这张牌初始具有 6 次闪耀。卡牌继续使用原有角色基类。牌面正文描述卡牌自身效果，闪耀标记、次数和公共特效由 Core 自动处理。

这个声明示例展示相关部分，完整构造函数和牌效写在角色实现中。特性名称及精确签名在首版 SDK 发布时确认。

### 4.3 特殊牌效扩展

普通闪耀牌采用上述声明即可。需要查询闪耀、赋予临时闪耀或主动耗尽的牌效使用对应公共接口。

| 拟定入口 | 用途 |
| --- | --- |
| `Shine.IsShineCard(card)` | 识别任意已接入 Mod 的共享闪耀牌 |
| `Shine.GetState(card)` | 读取剩余次数、上限、来源范围和待耗尽状态 |
| `Shine.GrantTemporary(card, uses)` | 为本场实例赋予临时闪耀 |
| `Shine.DepleteAfterCurrentResolution(card)` | 请求当前合法结算结束后耗尽 |
| `Shine.GetDepletedCards(player)` | 读取该玩家的耗尽档案 |
| `Shine.CountDepletedKinds(player)` | 按完整模型 ID 统计真实耗尽种类 |

`GetState` 返回只读快照，未具有共享闪耀状态的牌返回空值。耗尽奖励由该牌的专用回调提供。具体协议随 SDK 接口参考提供。

## 5. 闪耀使用约定

玩家显示为“闪耀N。”，表示这张实际牌剩余的整局使用次数。

- 各实际牌独立计次，剩余次数跨战斗保存。
- 普通闪耀牌每次实际出牌与原生重放各使用一次，耗尽在合法结算点统一处理。箭矢方式执行采用下述结算计次规则。
- 普通消耗保留已使用后的余量，升级恢复至该牌上限。
- 临时复制品使用自己的本场预算。永久耗尽奖励由对应真实永久来源产生。
- 已施加的能力按其本场持续时间结算。
- 闪耀箭矢牌在每次实际结算时扣 1 次闪耀。其他闪耀牌被作为箭矢打出时同样处理。布置和等待阶段记录待结算任务，各次重放也在实际结算时扣次数，整批合法结算结束后处理最终耗尽。
- 闪耀牌堆记录本局真实永久耗尽，重新获得产生新的实际牌生命周期。

新局采用 `core-shine@1`。携带旧 Karen 耗尽档案的存档采用 `karen-shine@legacy-1`，沿用每次原生出牌扣一次和普通消耗补满的旧规则。

角色的闪耀奖励候选、耗尽回血、遗物奖励、指定变形等内容通过角色自己的牌效和专用回调提供。公共识别可以作用于两边的共享闪耀牌，奖励池按效果声明来源。

### 5.1 闪耀牌公共特效

Core 从 Karen 迁入整套公共闪耀表现，并按卡牌状态自动播放。

- 常驻光效与卡框微光。
- 即将耗尽时的临界预警与出牌过程高亮。
- 实际耗尽时的卡牌消散、光效及飞入牌堆动画。
- 到达闪耀牌堆时的图标反馈。
- 闪耀牌堆查看界面的公共装饰。

卡牌声明闪耀次数后，Core 统一接入这些表现。“闪耀相关特效”开关统一控制常驻光效、临界提示及耗尽动画，资源与表现预算由 Core 管理。

### 5.2 共用衍生牌“空壳”

“空壳”随闪耀机制由 Core 提供，沿用 Karen 的 0 费技能衍生牌、消耗、无额外牌效。尝试普通复制或转交一张闪耀次数已耗尽的牌时，取得空壳。

普通耗尽按永久移除或牌面指定变化处理。耗尽档案与预览保留原牌信息，明确写明重新获得的效果按对应牌效建立新的实际牌生命周期。Core 自动处理这些操作的用途，角色作者按相应公共命令执行复制、转交或重新获得。

## 6. 对局、报错与 Web 页面

Core 加载后自动建立公共采集和发送流程，读取原生对局记录、角色模型、所属 Mod 与版本信息，统一处理快照、持久队列、请求、限流和重试。

长颈鹿画面由 Core 在游戏启动阶段统一播放。对局收集、报错收集及 Web 数据按默认流程工作，角色作者直接使用本体的模型和日志机制。

报错收集覆盖初始化后的标准错误流、引擎／脚本／Shader 错误，以及托管未处理和未观察任务异常。报告包括错误摘要、调用栈、游戏与 Core 版本、平台和已启用 Mod 版本。客户端与服务端沿用现有文本清理和聚合规则。

Core 自动从模型与牌池生成页面需要的角色、卡牌和遗物资料。服务端、报错收集器和对应 Web 页面由 Core 工程维护并独立部署，客户端通过独立 Core 订阅或 Karen 内嵌包分发。

Web 页面提供对局列表与详情、卡牌和角色统计、报错筛选、聚合次数与调用栈详情。页面中的 Mod 来源和版本按实际数据展示。

## 7. 接口与更新兼容

公开接口同一主版本保持稳定。已发布的程序集名、命名空间、公开成员签名、关键字 ID 和保存键继续提供，新能力通过增量接口发布。

Core 更新以旧角色 DLL 直接运行和旧存档读取作为验收条件。正式版、测试版提供相同的作者契约，游戏差异由对应适配处理。

共享规则随对局保存。Core 的用户配置由自身格式升级，业务存档与服务端数据按各自格式兼容。每次发行说明列出游戏目标、BaseLib 要求、接口范围和迁移内容。

作者接入复制与持续效果时使用以下入口：

- `CardCopies.Snapshot(card)` 捕获原模型的独立运行时快照，供持续能力读取；零闪耀余量仍保留原模型。
- `CardCopies.ForDeck/ForCombat` 按临时复制、转交或重新获得的用途创建实际牌。战斗复制保留本场费用、形态与投入，永久获得使用原生保存字段。
- `CardSelection.Choose` 处理最多三个选项的原生选择、标题、可跳过状态与选择上下文收尾。

这些入口分别声明 `card-snapshots@1`、`card-copies@1` 和 `card-selection@1`，要求 Core 1.2.0。

### 实际卡牌选择、升级与临时音乐

Core 1.4 提供 `CardPicking.Pick`，统一实际卡牌选择和结果校验。`CardUpgrades.Upgrade` 等待升级产生的后续牌效，原生模型与动作内的升级由 Core 自动衔接。`IMusicOverrides` 提供临时曲目和静默租约，释放后恢复被中断的音乐。能力声明见 `sdk/README.md`，接口见 `src/Api.V1/`。


## 1.5 自定义选择同步

PlayerChoices.ChooseIndex(context, player, optionCount, selectLocal) 统一自定义界面的原生选择编号、联机传输和重放。仅本地实时玩家调用 selectLocal，返回选项索引或 -1 取消；越界结果抛出异常，空选项直接返回 -1。传入选择上下文时，Core 在完成和异常时平衡选择信号；奖励同步等已经管理生命周期的入口传 null。角色负责候选顺序、界面显示和结果执行，使用该入口声明 player-choices@1，要求 Core 1.5.0。公开程序集版本保持 1.0.0.0。
