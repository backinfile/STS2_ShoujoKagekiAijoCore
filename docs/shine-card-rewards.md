# 闪耀牌奖励

奖励按接收玩家选池，在生成奖励时使用该玩家的 Rewards 随机数流确定牌，领取时不重新抽取。

1. 少歌角色优先使用自己的角色卡池；按当前单人／多人条件取已解锁候选，保留闪耀牌，排除基础牌、指定的 except 模型及牌自身的掉落限制。
2. 自身没有合法闪耀候选，或接收者不是少歌角色时，使用 Karen 卡池，并保留其跨角色掉落限制。
3. Core 的“闪耀的再生产”独立加入所有接收者的奖励候选，不影响是否回退角色卡池的判断。
4. 先按普通 42、罕见 42、稀有 15、再生产 1 的权重选择类别，再从该类别中等概率取一张。类别为空时，从全部合法候选中等概率取一张。
5. 未安装 Karen 且没有自身候选时，候选仅为公共再生产。except 对公共牌同样生效；所有候选均被排除时报告无合法奖励，不绕过排除项。

`ShineRewards.GetCandidates`、`Roll` 和 `Add` 共用上述规则。角色可以实现 `IShineRewardEligibility` 增加具体牌的掉落条件。`Add` 在战斗中预约战后奖励并添加数量标记，战斗外立即展示；沿用原生单牌领取、存档、联机同步及现有多奖励分组展示。

公共再生产保持原 ModelId `CARD.KAREN_SHINE_REPRODUCE`、基础 1 费／升级 0 费、闪耀 1 和原三语正文。它从接收者自己的耗尽档案中选择一张牌，使用公共 Reacquire 流程恢复永久属性并建立满次数的新生命周期，同时加入永久牌组和手牌；候选排除再生产自身。该牌及奖励显示、标记和资源由 Core 提供。
