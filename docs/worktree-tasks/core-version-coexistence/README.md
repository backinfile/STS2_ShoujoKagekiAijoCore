## 计划

沿用兼容包择版规则，验证 1.x 与新版同场时新旧引导的执行顺序，并确保进程只初始化一份 Runtime。

## 结果与验证

- 旧 ID 的 1.x 引导先启动时，通过随 2.0.1 交付的兼容候选转交。新版先启动时，旧 ID 用于满足依赖，旧 Runtime 跳过。实际 Runtime 继续执行既有候选择版，合并旧、新 ID 的角色需求。
- 随包提供 77 个旧 V1 类型转发。核对了 1.0.1、1.6.0、1.9.7 的公开类型覆盖范围。保留玩家保存的加载顺序。
- Core 2.0.1 已用 v0.107.1、v0.111.1、v0.113.0 引用构建，34 项引导择版校验和 54 项离线打包检查通过。
- v0.111.1 下 1.9.7 与 2.0.1 两种启动顺序均加载 2.0.1。旧版 Karen 和引用新版 API 的探针同时加载，仅注册一份 Core 配置。v0.107.1 下 1.0.1 先启动时也转交给 2.0.1。v0.111.1 仅装新版的启动通过。实机并存测试启用两种 ID。
