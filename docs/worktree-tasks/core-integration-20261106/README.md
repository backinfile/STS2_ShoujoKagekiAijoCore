## Brief task plan

以 README.md 与 docs/IMPLEMENTATION.md 为共同规范，建立隔离集成基线，并启动以下独立任务。各任务在自己的工作树修改、验证和提交，完整接口与运行接线在总装阶段核对。

| 工作 | 主要拥有范围 | 依赖 |
| --- | --- | --- |
| 01 基础工程与引导 | Bootstrap、Api.V1、Runtime、Compatibility、配置、SDK 打包和工程入口 | 文档基线 |
| 02 闪耀与公共玩法 | 闪耀、空壳、牌堆、快照、复制、重放、移牌和实际结算协议 | 01 的公共契约 |
| 03 音画与播放器 | 公共特效、绘制与音频、长颈鹿、衍生标记、音乐播放器与本地输入 | 01 的配置与资源契约、02 的闪耀状态 |
| 04 采集、服务与 Web | 采集客户端、队列、服务端、页面、资料导出与部署产物 | 01 的发现与生命周期契约 |
| 05 patches 与诊断 | 公共补丁、三档遗物限制、旧补丁交接、只读检查 | 01 的版本与配置契约 |
| 06 Karen 接入 | Karen 的源码迁移、兼容映射、依赖清单和随包构建 | 01 至 05 的可用产物 |
| 07 Junna 接入 | 闪耀声明、箭矢实际结算接入、依赖清单与随包构建 | 01、02、03 的契约与产物 |

Core 内部任务从此集成检出建立独立工作树，角色任务从各角色原始检出建立独立工作树。工作树统一采用 ../worktrees/<projectName>/<task-slug>。基础任务优先发布协作契约，模块任务保持自己的文件范围，总装负责顶层接线。

任务完成后，集中列出实际提交、验证、各目标分支和原有未提交状态，再按 $worktree-task 请求明确的合并确认。清理在集成验证后单独确认。
