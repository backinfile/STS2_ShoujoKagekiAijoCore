# 修复闪耀批次关闭后漏归档

## 用户原始输入

> 修复

该请求接续 [Core 闪耀归零残留调查](../core-shine-depletion-investigation-20261120/README.md)。

## 计划

验证迟到的子出牌归档失败，修复批次关闭后的归档责任，复核正常嵌套、出牌后存档及下一场战斗。核对旧存档字段能否识别历史残留。

## 实际变更

- 新结算跳过异步上下文中已关闭的批次，使用仍开放的最近祖先，或建立独立批次。
- 子批次收尾只向仍开放的祖先交接。关闭和接收互斥。没有可接收的祖先时，子批次执行现有耗尽流程。
- 增加定向回归，覆盖父批次正常等待、原生子结算在父批次关闭后才开始、原生子结算晚于父批次完成，以及迟开始的箭矢结算。

现存异常牌的存档仅保存 0/3 和两个 false 标记。公开状态接口可以写入相同字段，无法从这些值可靠地区分历史漏归档与牌效设置。此修复从结算入口防止新残留，已保存的异常牌需要按具体对局的牌实例恢复。

## 验证

- 修复前的 Beta 定向回归在迟开始的原生子结算断言失败。修复后，`tests/ResolutionChecks` 的结算测试在 v0.107.1、v0.111.1 和 Beta v0.113.1 的真实程序集引用上通过。
- 以已安装的 Core 1.9.7 包为基底替换 Beta Runtime 并更新哈希，测试包通过 SDK 严格校验。Beta Runtime 的 SHA-256 为 `1DFB8444D2B07CC360CD721B96DA13D2006989C04E6AFB1916916E4ACA6F726B`。
- 使用 v0.113.1 和纯那经 MCP 复测原场景，6 项断言全部通过。两张 1/3 的「渴望」分别在正常等待和迟开始的情形耗尽，永久原牌均移除且各归档一次。胜利存档没有残留「渴望」，下一场的战斗模型和起手均无对应空壳。
- 实机证据位于 `out/tmp/fix-shine-batch/beta-fixed/`，包括结果、截图和 11.75 秒内部混音录像。169 次窗口检查均为最小化，前台焦点违规数为 0。
